# E-Commerce Customer Analysis & RFM Segmentation

An end-to-end Python data analytics project analyzing transactional retail data, identifying purchasing trends, evaluating product performance, and segmenting customers using Recency, Frequency, and Monetary (RFM) modeling.

---

## 1. Project Overview & Problem Statement
Modern e-commerce platforms process millions of transactional rows but frequently struggle with customer retention, basket size optimization, and churn prevention. Treating all customers uniformly leads to inefficient marketing spend, generic promotional discounts, and missed high-value upsell opportunities.

This project delivers a data-driven customer intelligence framework using transactional data from a UK-based online gifts and homeware retailer. By processing over 540,000 raw transaction logs, establishing rigorous cleaning rules, and implementing RFM customer segmentation, this project categorizes 4,338 unique customers into actionable cohorts to drive targeted lifecycle retention strategies.

---

## 2. Business Objectives & Analytical Questions
1. **Sales Trajectory**: How has monthly revenue trended over the operating period, and what seasonality governs ordering behavior?
2. **Product Catalogs**: Which stock keeping units (SKUs) generate the largest revenue and unit volume?
3. **Geographic Concentration**: What percentage of revenue originates from the domestic UK market versus international export markets?
4. **Behavioral Timing**: What peak hours of the day generate the greatest volume of order placements?
5. **Customer Segmentation**: How are customers distributed across Recency, Frequency, and Monetary dimensions, and what fraction of revenue is generated by "Champions" versus "At Risk" cohorts?

## 5. Dataset Attribution & Data Dictionary

- **Dataset Source**: [UCI Machine Learning Repository — Online Retail Dataset](https://archive.ics.uci.edu/dataset/352/online+retail)
- **Timeframe**: December 1, 2010 to December 9, 2011
- **Domain**: Registered non-store online retailer based in the UK.

### Data Dictionary
| Column Name | Data Type | Description | Cleaning Decision |
| :--- | :--- | :--- | :--- |
| `InvoiceNo` | String / Object | 6-digit transaction identifier. If code starts with letter 'C', it indicates a cancellation. | Stripped whitespace; excluded 'C' cancellations. |
| `StockCode` | String / Object | 5-digit product code. | Preserved SKU structure; cleaned strings. |
| `Description` | String / Object | Nominal product name. | Stripped extraneous spaces; noted 1,454 missing raw entries. |
| `Quantity` | Integer | Quantity of units generated per transaction line. | Filtered strictly for `Quantity > 0` (negative = returns). |
| `InvoiceDate` | Datetime | Invoice timestamp in format `%m/%d/%Y %H:%M`. | Parsed to datetime; derived `YearMonth`, `Hour`, `DayOfWeek`. |
| `UnitPrice` | Float | Product price per unit in GBP sterling (£). | Filtered strictly for `UnitPrice > 0` (zero/negative = bad debts). |
| `CustomerID` | Float / String | 5-digit unique customer identifier. | Filtered missing values (24.9%) specifically for customer RFM analysis. |
| `Country` | String | Name of the country where the customer resides. | Cleaned strings; mapped UK vs Export markets. |

## 9. Assumptions & Limitations
1. **Unregistered Transactions**: 24.9% of transactions lacked a `CustomerID`. These were incorporated into overall macro sales trends and product-level demand analyses, but excluded from customer-level RFM segmentation.
2. **Postage Items**: Items like `DOTCOM POSTAGE` and `POSTAGE` are cataloged as line items; while reflecting actual cash receipts, they represent logistics fulfillment rather than physical merchandise.
3. **Study Horizon**: The dataset concludes on December 9, 2011; thus, December 2011 is a partial month.

## 10. Interview Preparation: 10 Core Questions & Answers

### Q1: Why did you filter out transactions where `Quantity <= 0` and `UnitPrice <= 0`?
**Answer**: In retail transaction data, negative quantities represent product returns or order cancellations, and unit prices of zero represent samples, promotional giveaways, or accounting write-offs. Mixing returns with gross purchases without an explicit event model distorts Average Order Value (AOV) and product popularity rankings.

### Q2: How did you calculate Recency, and why did you use `max(InvoiceDate) + 1 day` as the anchor?
**Answer**: Because this is a static historical dataset ending in December 2011, using `datetime.now()` would falsely indicate that all customers have been inactive for over a decade. Setting the reference date to one day past the maximum observed transaction date allows us to measure recency relative to the operational snapshot.

### Q3: What is the mathematical difference between `nunique()` and `count()` in Pandas?
**Answer**: `count()` returns the total number of non-null rows in a group (e.g., total item rows purchased), whereas `nunique()` computes the distinct count of unique values (e.g., the number of distinct order invoices placed by a customer). For customer purchase frequency, `nunique('InvoiceNo')` is required.

### Q4: Why did you use `pd.qcut` instead of `pd.cut` for RFM scoring?
**Answer**: `pd.cut` divides values into equal-width bins (e.g., intervals of £0-£500, £500-£1000), which creates heavy skew when monetary spend follows a Pareto distribution. `pd.qcut` divides data into equal-frequency quantiles (quartiles), ensuring an evenly distributed ranking scale (1 to 4) regardless of skewness.

### Q5: How did you handle duplicate transactions in the dataset?
**Answer**: We called `.drop_duplicates()` after verifying that identical timestamps, customer IDs, stock codes, and quantities represented accidental duplicate log entries, which removed 5,268 redundant lines.

### Q6: How do you handle missing `CustomerID` records without losing macro revenue insights?
**Answer**: We decoupled macro revenue analysis from micro customer segmentation. Macro revenue and SKU volume analyses retain guest checkouts, whereas the RFM pipeline filters strictly for records where `CustomerID.notnull()`.

### Q7: What business recommendation would you provide regarding the "Champions" segment?
**Answer**: Champions generate 61% of total customer revenue despite making up only 30% of the customer base. The business should prioritize retention over acquisition: deploy VIP loyalty tiers, early access to holiday collections, and dedicated customer support to protect this revenue stream.

### Q8: What is the formula for Average Order Value (AOV), and what was the result?
**Answer**: $\text{AOV} = \frac{\text{Total Revenue}}{\text{Total Unique Orders}}$. For this cleaned dataset: $\frac{£10,642,110.80}{19,960} = £533.17$.

### Q9: Why was `encoding='unicode_escape'` required during CSV loading?
**Answer**: The raw UCI dataset contains European currency symbols, accents, and special characters in item descriptions that violate standard UTF-8 parsing, resulting in a `UnicodeDecodeError` unless parsed with `unicode_escape` or `latin1`.

### Q10: If you had more time, how would you extend this customer analysis?
**Answer**: I would implement **Customer Lifetime Value (CLV)** predictive modeling using the BG/NBD and Gamma-Gamma probabilistic models, and build an automated churn prediction classifier using Scikit-Learn.
